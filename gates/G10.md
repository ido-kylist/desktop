## The five mutations

A test that cannot fail is decoration. Each of these was applied, the relevant spec was run,
the failure was observed, and the change was reverted. `git diff` after each revert showed only
test and doc files, so what is committed is an unmutated production tree.

| # | Mutation | What failed |
|---|---|---|
| 1 | `db/index.ts`: checksum guard disabled (`if (false && …)`) | the two drift tests — "refuses a database whose applied migration was edited" and "refuses drift in a mid-chain migration" |
| 2 | `db/index.ts`: apply only `MIGRATIONS.slice(0, 6)` | 8 upgrade tests, all on `expected 6 to be 7` |
| 3 | `knowledge/service.ts`: document title becomes `${title} ${config.apiKey}` | the flow test, reporting `['documents']` |
| 4 | `db/repo-mcp.ts`: `insertApproval` writes the key into `args_json` | the flow test, reporting `['mcp_approvals']` |
| 5 | the test's secret backend returns plaintext from `encrypt` | five assertions, including the file scan naming `['secret.bin']` |

Mutations 3–5 are the ones that matter for this gate: they prove the new scan surfaces are
live, not just the generic "something is missing from the whole dump".

## Defects this gate caught

None of these were found by a user; all of them were found by doing the work the gate asked for.

| Defect | How it surfaced | Fix |
|---|---|---|
| **The migration spec only ever built v1.** Its name said "upgrade", and the only version it constructed was v1 — a user on v3 had no test | Read the fixture, then asked what the other five shipped versions would do | `buildDatabaseAt(path, version)` applies 1…n and seeds what that version could hold; the matrix covers 1…7 |
| **The redaction disk scan was not recursive.** `allBytes` read one directory level, and the data dir now has `knowledge/` and `attachments/` under it | Extending the scan to a full flow whose files land in subdirectories | Recursive walk; the assertion now also names the leaking file |
| **`SECURITY.md` pointed at the wrong lines and the wrong contract.** It said 14 channels (there are 46), protocol v1 (it is 9), and cited `index.ts:57` for `enableSandbox` (it is `:76`) | Every claim was re-verified against the tree to add the D7/D8 sections | All 62 items re-derived from `grep`; the header now states which tree the numbers describe |
| **`vitest` had no `@shared` alias,** so no test could import a main module that registers IPC channels — the contract import failed at load | The redaction flow needed the real `attachments.add` handler | `vitest.config.ts` gained the alias the app build already had; purely additive |
| **A `Buffer` column is invisible to a `JSON.stringify` scan.** The first draft of the table scan serialised rows to JSON, which turns a BLOB into `{"type":"Buffer","data":[…]}` — numbers that can never match a canary | Reading the scan rather than trusting it, while the soak ran | `columnText` decodes `Buffer`/`Uint8Array` to latin1, the same way the file scan reads bytes |

The last one is the one worth repeating: a scan that cannot see a column is worse than no scan,
because it reports "clean".

## What was not measured, and why

- **The renderer's memory.** The soak is headless. A DOM leak in the transcript would not show
  up. Recorded in `BACKLOG.md`.
- **A real provider.** Everything runs against `mock/server.mjs`. No credential exists in this
  environment, and inventing one would be a lie. The provider boundary — header, SSE parse,
  error mapping — is exercised; a paid endpoint's latency and failure shapes are not.
- **The packaged bundle under soak.** `tests/e2e/packaged.spec.ts` proves the installed bundle
  boots and completes a turn; it does not soak it.
- **A v1→v7 upgrade from a *captured* v1 file** (a database written by the released binary). The
  fixture applies the same migration SQL this build ships, so it proves the chain and the
  checksum guard; it cannot prove that a shipped binary's page layout matches. Recorded in
  `BACKLOG.md`.
- **Concurrent generations, stop-mid-stream, regenerate-during-send.** The soak is sequential.
- **Disk growth over 30 minutes.** Row counts are reported; bytes are not.
- **Windows and Linux.** One machine, macOS arm64.
