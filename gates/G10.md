# Gate G10 — hardening (lite)

**Verdict: PASSED, narrowed** · 2026-11-15 · phase D10

The plan's D10 is six hours of soak testing, redaction proof, migration tests, e2e and a
twenty-item security dossier. Under the cut line this is scoped to the four items that carry
real risk. Everything omitted is named below, not implied.

## Delivered

| Item | Evidence |
|---|---|
| **Migration upgrade is a test, not a claim** | `tests/integration/migration-upgrade.spec.ts` — builds a real v1 database with migration 1's recorded checksum, opens it through `openDatabase`, and asserts: version 2, the `active_leaf_id` column exists, the legacy row survived with a null leaf, the pre-existing FTS index still answers `MATCH`, and the ledger holds both migrations in order. A second test edits an applied migration's checksum and asserts the opener refuses with `checksum mismatch`. |
| **Key redaction proven, and mutation-tested** | `tests/integration/redaction.spec.ts` — a canary shaped like a real key. It must survive a round trip (so the rest is not vacuous), be absent from **every byte on disk**, be absent from the masked value, appear **only** in the `Authorization` header, and be absent from the URL, the request body, the outcome, and any thrown error. Mutation check: replacing the encryptor with plaintext fails all four. |
| **Security dossier with file:line** | `docs/SECURITY.md` — isolation, bridge, CSP, credentials, network and supply chain, each with the line that proves it, plus an explicit "not evidenced" section. |
| **Packaged e2e widened** | `tests/e2e/packaged.spec.ts` — the installed bundle now completes a chat turn against the mock and persists a thread, not just a boot check. |
