## Decisions

- **`chat.regenerate` takes the assistant message id** — the button sits on that message. The
  contract was ambiguous; this is the call.
- **Regenerate makes the new sibling the active leaf** in the same transaction, so the next turn
  continues from the answer on screen.
- **`setActiveVariant` does not bump `updated_at`** — switching a branch is a view action, and
  bumping would reorder the sidebar under the cursor.
- **`variants` includes the message itself**, ordered `created_at` then `rowid` so two
  same-millisecond rows from one regenerate stay ordered.

## Migration proof

still matched legacy text, and a second open stayed at 2 without re-applying. **That proof is
not yet a committed test** — see `BACKLOG.md`.
