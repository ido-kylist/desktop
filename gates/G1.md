## The outstanding leg, stated plainly

`tests/e2e/chat.spec.ts` proves the mechanical claim: send against the mock, watch tokens
arrive, quit, relaunch with the same user-data dir, conversation is still there. What it does
not prove is a real provider: no API key exists in this environment, and inventing one would
be a lie. Everything up to the provider boundary is exercised — `safeStorage` encryption,
Bearer attachment, SSE consumption, error mapping for 402/429/truncated.

To close it, the owner needs to enter a key in the app (or set it via `secrets.setKey`) and
repeat the relaunch. Nothing in the code needs to change.
